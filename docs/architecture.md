# 架构约束

项目采用 TypeScript 模块化单体后端与 Electron 桌面客户端，通过网络接口分离。日常在当前 Mac 上开发，目标支持 Windows、macOS 及局域网跨设备连接；已接通能力见 [项目说明](../README.md)，Pi 可复用能力见 [能力导航](pi.md)。

## 模块划分

| 模块 | 职责与当前范围 |
| --- | --- |
| `desktop` | 用户界面、后端连接设置和临时展示状态 |
| `api` | 前后端共享的数据契约 |
| `backend` | 网络接入、连接认证与应用组装 |
| `runs` | 会话与执行编排、重复请求处理、取消和状态管理 |
| `runtime` | Agent 单次任务的模型与工具循环、上下文准备入口和执行控制 |
| `provider` | 模型服务接入与协议差异隔离 |
| `tools` | 实际可执行能力，当前提供只读后端时间工具 |
| `storage` | 会话、消息、任务与续接历史的持久化 |
| `secrets` | 集中管理并读取后端凭据 |
| `conversations`、`context`、`memory` | 规划中的独立会话、上下文与长期记忆职责；现有基础由相关模块承接，按实际需求拆出 |
| `channels`、`delivery` | 规划中的聊天平台接入与消息投递 |

```text
Electron → 网络契约 → 后端接入 → 会话与任务编排
                                  ├→ 存储：保存状态与历史
                                  └→ Agent 运行时
                                       ├→ Provider：调用模型
                                       └→ Tools：执行动作并返回结果
```

模型单轮推理由 Provider 提供，运行时决定如何继续循环，任务编排决定如何关联会话、保存状态和响应客户端。应用入口负责组装这些能力，将凭据注入所需适配器。

各模块的主要能力、关联模块及关联原因、核心类与入口导航见 [Provider](modules/provider.md)、[运行时](modules/runtime.md)、[后端与存储](modules/backend.md)、[桌面客户端](modules/desktop.md)。具体接口、字段和实现直接查阅源码。

## 接驳原则

- 大模块通过明确的公共契约和接驳层交互，禁止跨模块读取内部状态、私有文件或数据库表。
- 接驳层承接能力调用和格式转换；业务规则留在负责该能力的模块，具体 SDK、Pi 和存储实现不向业务层泄漏。
- 契约归提供能力的模块或使用该能力的业务端口所有，应用入口组装具体实现。按实际需求建立薄接口，不复制底层库的整套 API，也不为每对模块增加中间服务。
- 开发前查阅已有能力，优先复用或改造项目资产；有实际需求再创建模块、抽象或服务。

## 数据与执行边界

- 后端承担 Agent、工具、会话、记忆及全部业务数据；前端唯一持久化内容为后端连接设置，访问令牌受系统加密保护。首次设置并验证连接后才进入主界面。
- 客户端与后端可以同机或跨设备运行，均使用网络契约。工具默认操作后端机器；客户端文件不能直接当作后端本地路径。
- 会话历史、任务状态、长期记忆分别管理。模型上下文是本轮选取的数据视图，摘要和索引不取代原始记录。
- 对话顺序依据消息体创建时间；执行与投递的状态变化独立记录。模型生成完成不代表工具执行或平台投递成功。
- 客户端断线、关闭或切换会话不等于取消任务。当前后端保留历史并标记异常中断，不自动恢复或重放工具；后续带副作用能力需要明确幂等与结果核实规则。
- 工具在实际执行入口检查参数和授权；外部网页、文件和工具结果不能提升系统权限。记忆与资料先按身份和任务范围筛选，再判断相关性。
- 凭据集中在被 Git 忽略的 `secrets/`，业务数据与凭据分开保存，密钥不得进入日志或模型上下文。

## 演进原则

快速迭代直接采用当前最优方案，默认不维护向后兼容。调整接口、配置、文件位置、数据格式或实现时，同步更新调用方、相关文档与测试，删除失效方案；不增加旧格式回退、过渡分支、兼容包装或自动迁移。只有用户明确要求的具体场景才保留兼容；已确认支持的外部协议与平台仍属于产品要求。取消兼容不代表可以擅自删除用户数据。

文档以模块概览和源码导航为主，值得展开的内部主题按需拆子文档并同步维护；内容边界与维护方式见 [文档规则](documentation.md)。
