# 架构约束

本文记录当前开发约定，不是已实现功能清单。当前仅有文档和 Pi 核心源码，业务模块尚未建立。只有实际开发对应能力时才创建目录和接口。

## 整体结构

采用 TypeScript 模块化单体。入口负责组装依赖，业务模块通过明确接口协作；初期不引入微服务、通用插件平台或多 Agent 调度框架。

```text
平台消息 / 定时事件
  → 身份识别、消息去重、确定会话
  → 创建或推进执行任务
  → 组装上下文
  → Pi 运行时调用模型
      → 工具请求 → 权限与参数检查 → 执行 → 结果返回循环
      → 等待用户 → 持久化等待状态
      → 回复或文件 → 保存结果 → 投递目标平台
```

## 模块职责

以下为预期的 `src/` 模块边界，按需落地。

| 模块 | 职责 |
| --- | --- |
| `channels` | 接收平台事件并转换为内部消息；实现平台发送接口，不决定任务语义 |
| `conversations` | 身份绑定、会话归属、历史和消息顺序 |
| `runs` | 推进执行，管理排队、取消、超时、等待和恢复 |
| `context` | 选择规则、历史、任务状态、记忆与工具，分配上下文预算 |
| `runtime` | 隔离 Pi 和模型供应商接口，将运行事件转换为本项目事件 |
| `tools` | 工具注册、参数校验、权限判断、执行和结果记录；业务 API 通过工具适配 |
| `memory` | 记忆写入、检索、修正、失效和删除 |
| `delivery` | 管理回复投递、限速、重试和发送状态，调用平台发送接口 |
| `storage` | 实现持久化接口、事务、迁移与附件存储 |

## 模块接驳

所有大模块之间的交互都经过明确的公共契约和接驳层。接驳层是模块边界的组成部分，可以由模块公共入口和必要的适配器实现，不要求每对模块新建一个中间服务。

- **公共契约**说明对外能力、输入输出、错误、事件及相关执行语义；类型和 Schema 以代码为准，文档解释职责与容易误解的约束。
- **接驳实现**处理接口调用、数据格式转换、外部错误归一化及取消信号传递；业务决策留在负责该能力的模块。
- **内部实现**不跨模块暴露。调用方不能直接读取其他模块的表、内部状态或私有文件，也不能借公共入口导出内部对象来绕过边界。
- **契约归属**由提供能力的模块或使用该能力的业务端口持有；具体适配器实现契约。只有确实跨模块复用的类型才提取为公共契约，避免建立杂物式的 `common` 或 `utils` 模块。
- **依赖组装**由应用入口完成。`runs` 负责流程编排；平台、存储和 Pi 适配器实现业务接口，业务规则不反向导入这些具体实现。
- **演进方式**按实际场景增加能力，不逐个转发底层库的全部方法。改变公共契约时同步检查调用方、接驳实现、必要测试及相关文档。

例如：`runs` 通过 `AgentRuntime` 使用 Pi，通过上下文接口获取本轮输入；`delivery` 通过平台发送接口投递。替换底层实现时，影响应尽量集中在对应接驳处。

Pi 专有类型尽量停留在 `runtime`；工具通过本项目的工具描述接入，在适配处转换为 Pi 工具。先围绕实际调用点建立薄接口，不复制整套 Pi API。

## 数据归属

- **平台身份与平台话题**：标识某个平台上的人和聊天位置；跨平台身份通过明确绑定关联，不凭昵称猜测。
- **Conversation**：长期交流容器，包含多条消息和多次执行。
- **Run**：一次具体任务，独立保存目标、状态、进度、结果及等待事项。
- **Message**：保存实际输入、模型输出和工具结果，保留来源与关联 ID。
- **Memory**：可检索的长期事实或偏好，包含来源、时间、适用范围及是否由用户明确确认。
- **Delivery**：一次对外投递及其状态，与模型是否完成生成分开记录。

初期使用 SQLite 保存结构化数据，附件使用文件系统；具体表结构在实现对应场景时确定。会话历史、运行状态和长期记忆独立管理。摘要和检索索引是派生数据，不取代原始记录。

## 执行与恢复

- 平台事件有稳定去重键；同一会话初期串行处理普通输入。取消或中断作为明确控制操作处理。
- Run 状态至少区分排队、运行、等待用户、成功、失败、取消；状态变化需要持久化。
- 请求发出、工具执行完成、结果保存、平台投递成功是不同事实，不互相代替。
- 外部写操作记录调用 ID 和幂等键；是否允许重试取决于工具能力。
- 超时后如果无法判断外部动作是否已经成功，进入结果待核实状态；不得直接重试并假设没有副作用。
- 中断恢复依赖持久化状态和已记录结果；重放事件默认不重新执行外部动作。
- 循环有可配置的时间、轮数和资源预算，并将取消信号传递给模型和工具。

## 上下文与权限

- 按会话、用户和任务范围筛选数据，再进行相关性检索；跨平台关联不代表自动共享全部历史。
- 每次模型调用能追踪所用规则版本、历史范围、记忆来源和工具集合；观测记录遵守数据脱敏约束。
- 工具结果与外部网页、文件均属于资料，不能提升指令权限。
- 权限在实际执行工具时检查；模型可见工具列表不能代替授权检查。
- 长期记忆可修正和删除，明确区分用户陈述与模型推断；暂不强制引入向量数据库。

## 验证原则

程序检查覆盖状态、接口和失败路径；场景评测验证工具选择、记忆范围和任务完成情况。优先验证消息去重、取消、恢复、权限与工具副作用。真实平台和模型测试显式配置，不作为默认本地测试的隐含行为。
